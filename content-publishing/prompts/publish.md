# 책 원문 → 네이버 블로그 공개 발행

docs/OPERATIONS.md, docs/requirements.md와 config.local.json, state.local.json을 읽는다. 아래 오늘 대상은 계산된 계획일 뿐이다. 실제 게시물과 기존 진행기록을 대조하고 이미 게시됐으면 중복 발행하지 않는다. 상충 시 기록을 바로잡기 전 공개하지 않는다.

원문 목차와 해당 범위를 실제로 읽고 작성·이미지 생성·편집·공개 발행·검증까지 실행한다. 첫 PDF나 장 내부 소제목을 책의 장으로 혼동하지 않는다. 사용자 책에서는 원문 문체를 우선해 경제 지식 없는 고등학생도 이해할 질문·장면·짧은 문단으로 쓴다. ‘원고에서는’, ‘저자는’ 같은 메타 해설을 반복하지 않는다.

후킹 제목, 본문 최상단 필수 썸네일, 도입, 목차, 소주제 4~5개와 각 이미지·설명, 결론, 마무리, 출처를 구성한다. 썸네일을 먼저 생성하고 1254×1254px로 검수한다. 소주제 이미지는 별도 4~5장, 기본 9:16이다. 색은 주제에 맞추고 한글·잘림·사실을 확인한다.

실제 구분선은 짧게 가운데 배치한다. 목차 제목은 24 굵게, 소제목·결론 제목은 24 굵게 가운데, 본문은 왼쪽 본문 크기다. 마지막 마무리는 다시시작해·이탤릭, 출처 블록만 바른히피·이탤릭이다. 존재하지 않는 인용이나 경험을 만들지 않는다.

연결된 로그인 Chrome에서 설정된 계정과 카테고리를 확인하고 전체공개로 발행한다. 원고·이미지·프롬프트·출처 범위를 output/날짜_책_범위에 보관한다. 실제 게시물에서 제목·카테고리·썸네일·이미지 수와 순서·서식을 확인하고 증빙을 저장한다. manifest.json을 작성해 verify를 통과한 후에만 state.local.json의 completed와 posts를 갱신한다. verify는 로컬 증빙 검사이며 실제 사이트 확인의 대체가 아니다.

로그인·캡차·연결·파일 접근·필수 서식 문제는 초안을 보존하고 확인된 원인·완료 단계·저장 위치·사용자 조치를 보고한다. PC가 꺼져 있었는지 로그 없이 단정하지 않는다. 앱 재개 시 누락 실행을 점검하고 중복 여부를 확인한다. 과거 실행 누락을 무조건 연속 공개 발행으로 메우지 않는다.
